# 선을 넘어, 함께 — 통합접수창구

경계선지능인 지원사업 신청자를 접수하고 아동·청소년/청년 서비스를 연계하는 한국어 관리 웹앱입니다. React + Vite 화면, Vercel Node API, Firebase Firestore 저장소로 구성했습니다.

## 개발 결과와 현재 연결 상태

- 로그인 구분, 전체 명단, 사업별 프로그램 필터, 프로그램별 상태, 대상자 상세, 참여 이력·기관 의견, 지원 참고사항, 관리자 전용 민관협의체, 기관·계정 관리 구현.
- 관리자 외에는 배정된 대상자만 조회. 프로그램 의견 작성은 해당 프로그램 담당 기관으로 제한. 배정된 기관끼리는 대상자의 공동지원 기록과 참고사항을 공유하는 정책.
- 실운영 로그인은 서버의 scrypt 해시 및 HttpOnly 세션 쿠키 사용. 초기 관리자와 새 계정은 비밀번호 변경 후 업무 가능. 관리자는 계정 중지/재개·임시 비밀번호 재발급 가능. 변경·중지 시 기존 세션 무효화.
- 화면은 생년월일 6자리 + 별도 접수번호로 표시. 생년월일은 고유 ID가 아닙니다. 이름은 별도 컬렉션에 저장하고 관리자 열람 시 감사 기록 생성 및 30초 뒤 화면에서 숨김.
- 시트 열 연결·가져오기 검증·수동 동기화·제출 트리거 코드 포함. 제공된 비공개 시트의 실제 헤더와 행은 열람하지 못했으므로 정확한 매핑과 실데이터 동기화는 연결 후 검증해야 합니다.
- 실제 GitHub 업로드, Vercel 배포, Firebase 프로젝트 생성/서버 비밀 설정, 운영 데이터 테스트는 인증 연결 후 진행합니다. 이 문서는 배포 완료를 의미하지 않습니다.

## 가상 데이터로 로컬 실행

Node.js 22 이상에서 실행합니다.

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

터미널에 표시된 주소(기본 http://127.0.0.1:5173)를 열면 됩니다. 이 폴더에 동봉한 `미리보기_실행.cmd`로도 시작할 수 있습니다. 개발 서버를 종료하려면 그 창에서 Ctrl+C를 누릅니다.

체험 관리자: **사서원 / 1234**. 체험 기관: **연계기관 / demo1234!**. 모든 데이터는 가상이며 브라우저 localStorage에 저장됩니다. 실제 개인정보를 입력하지 마세요. 체험 모드의 프런트엔드 권한은 시연용이며 운영 보안을 제공하지 않습니다. 실운영은 `VITE_DEMO_MODE=false`로 다시 빌드해야 합니다.

## 실운영 연결 순서

1. Firebase에서 프로젝트와 Firestore 데이터베이스를 만듭니다. 조직 요구에 맞는 데이터 위치를 먼저 선택합니다. 앱의 자료는 Firestore에 저장됩니다. 파일 첨부 기능은 이번 범위에 없으며 Storage 접근은 닫아 두었습니다.
2. Firebase Admin 서비스 계정의 서버 자격증명을 준비합니다. 채팅·소스·GitHub에 비밀키를 넣지 않습니다. Vercel의 서버 환경 변수에 `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`를 설정합니다. 비밀키의 줄바꿈 또는 `\n` 형식을 지원합니다. 환경 변수는 `.env.example` 참고.
3. Firestore/Storage 규칙을 적용합니다. 제공된 규칙은 모든 클라이언트 직접 접근을 거부합니다. 서버 Admin SDK는 규칙을 우회하므로 모든 요청에서 API가 역할과 배정을 검증합니다. 이 규칙은 **이 앱 전용 새 프로젝트** 기준입니다. 기존 프로젝트의 규칙을 덮어쓰기 전에 다른 앱 영향을 확인합니다.
4. Google Cloud에서 Google Sheets API를 활성화합니다. 제공된 시트를 서버 서비스 계정 이메일에 **뷰어**로 공유합니다. 링크 공개/웹 게시로 바꾸지 않습니다. 상세 연락처는 앱에 수집하지 않습니다.
5. `integrations/Code.gs`를 해당 응답 시트의 Apps Script에 넣고 `prepareExistingResponses`를 실행합니다. 기존 응답 끝 열에 고정 `접수ID`가 추가됩니다. 시트 생년월일 열은 선행 0이 유지되도록 일반 텍스트 또는 6자리 사용자 서식으로 설정합니다. `대상구분` 열은 `아동청소년` 또는 `청년` 값이어야 하며 없다면 추가/정리합니다. 자동 판단은 하지 않습니다.
6. 로컬의 비밀 `.env.local`에 서버 환경 변수를 설정한 뒤 초기 관리자 생성: `node --env-file=.env.local server/bootstrap.js`. 계정이 이미 있으면 create가 실패하며 기존 계정을 덮어쓰지 않습니다. 최초 **사서원 / 1234** 로그인 후 10자리 이상으로 변경해야 접수 내용을 조회할 수 있습니다. 초기 생성 직후 담당 관리자가 비밀번호를 변경하세요.
7. GitHub `https://github.com/khr3171/app_line`에 소스를 올리고 Vercel에서 이 저장소를 Import합니다. Vite 프레임워크, Node 22 이상, 빌드 `npm run build`, 출력 `dist`. API는 `/api/index.js` Vercel Function으로 동작합니다. 정적 파일만 별도 호스팅하면 실운영 API는 동작하지 않습니다.
8. Vercel에 `VITE_DEMO_MODE=false`, `APP_ORIGIN=https://확정된도메인`, 위 Firebase 서버 변수, `GOOGLE_SHEET_ID`, `GOOGLE_SHEET_GID`, `SHEETS_WEBHOOK_SECRET`을 설정하고 재배포합니다. Preview 환경은 별도 Firebase 프로젝트를 사용하세요. `APP_ORIGIN`은 브라우저 주소와 정확히 일치해야 합니다. 모든 비밀 변수에 `VITE_` 접두사를 붙이지 않습니다.
9. 관리자로 로그인 → 계정 및 연동 관리 → 시트 열 불러오기 → 열 연결 → 미리보기 오류 확인 → 열 연결 저장 → 지금 동기화. 오류가 하나라도 있으면 전체 가져오기를 중단합니다. 점수는 단순 접수 기록이며 의학적 판정이나 자동 대상자 선정을 수행하지 않습니다.
10. Apps Script의 Script Properties에 `APP_URL`과 `WEBHOOK_SECRET`을 설정합니다. 서버와 같은 무작위 32바이트 이상의 비밀값을 사용합니다. `installTriggers`를 실행하고 구글 권한을 승인하면 폼 제출 후 자동 동기화되며 매시간 실패분 재시도가 동작합니다. 기존 트리거는 중복 생성하지 않습니다.
11. 가상/테스트 응답으로 신규 접수, 동일 응답 재동기화, 기존 의견 보존, 기관 간 권한 차단, 계정 중지, 비밀번호 재발급을 확인한 후 실제 운영합니다. 불필요한 테스트 자료는 운영 전 제거합니다.

## 시트 데이터 계약

열 제목은 관리 화면에서 선택하므로 고정된 이름이 아니어도 됩니다. 값은 아래 형식을 따릅니다.

| 항목          | 필수   | 형식                                                           |
| ------------- | ------ | -------------------------------------------------------------- |
| 접수ID        | 예     | 비어 있지 않은 영구 UUID. 정렬하거나 행을 이동해도 바꾸지 않음 |
| 생년월일      | 예     | YYMMDD 또는 YYYYMMDD. 선행 0 유지                              |
| 대상구분      | 예     | 아동청소년 / 청년                                              |
| 신청 프로그램 | 예     | 아래 지원명과 일치. 여러 개는 쉼표·세미콜론·줄바꿈으로 구분    |
| 이름          | 아니오 | 관리자 전용 별도 저장                                          |
| 선별검사      | 아니오 | 숫자. 빈칸은 미입력. 자동 해석 없음                            |
| 당부말씀      | 아니오 | 2,000자 이내                                                   |
| 접수 일시     | 아니오 | 구글 폼 응답 시각. 날짜 인식 가능한 ISO 형식 권장              |

아동·청소년: 진단검사 지원 / 부모상담 및 치료프로그램 / 방학단기프로그램 / 바우처 지원 연계 / 유소년 축구교실

청년: 상담 / 사례관리 계획 / 자립교육 / 일경험처 연계 / 사후관리

실제 폼의 선택지 명칭이 다르면 폼/시트 변환 열에서 위 명칭으로 맞추거나 코드의 프로그램 목록을 실제 명칭에 맞게 변경합니다. 모호한 응답을 임의로 분류하지 않습니다.

같은 `시트 ID + 접수ID`는 같은 대상자 기록으로 갱신합니다. 생년월일로 합치지 않습니다. 기존 서비스 상태, 기관 배정, 의견, 참고사항을 보존하며 새로 신청한 프로그램만 추가합니다. 시트에서 응답이나 프로그램이 사라져도 앱 기록을 자동 삭제하지 않습니다. 동기화는 문서별 트랜잭션이며 전체 시트 원자적 커밋은 아닙니다. 중간 장애는 재동기화로 복구합니다. 소규모 통합접수 운영을 위한 초기 버전으로 대량 데이터에서는 페이지 단위 서버 조회와 작업 큐 확장이 필요합니다.

## 권한과 저장 구조

`accounts` (관리자 관리), `sessions` (8시간), `rateLimits` (로그인 제한), `agencies`, `cases` (공동지원 기록), `privateCases` (이름), `meetings` (관리자 전용), `audit` (관리 변경·로그인·이름 열람), `settings/sheets`, `system/sheetLock`.

기관은 배정 대상자 전체 지원 기록을 함께 열람하는 정책이며, 의견 작성은 자기 기관에 배정된 프로그램으로 제한됩니다. 기관 간 공유 범위를 다르게 운영하려면 API의 응답 필드를 조정해야 합니다. 생년월일·점수·의견도 개인정보에 해당할 수 있으므로 권한이 있는 담당자만 이용합니다. 이름 열람 후 숨김은 화면 보호 기능이며 이미 열람한 정보의 브라우저 메모리 소거를 보장하지 않습니다.

세션·로그인 제한은 만료 검사 후 차단하며 자동 삭제 TTL은 아직 설정하지 않았습니다. 운영 프로젝트의 TTL/감사기록 보관기간·백업·복구·자료 삭제 절차는 운영 기관 정책에 맞춰 설정해야 합니다. 로그인·계정 변경 등 감사 로그는 서버에 기록하지만 이 버전에는 감사로그 조회 UI, 첨부파일, 다중요소 인증, 이메일 알림은 없습니다.

## 확인 명령

```powershell
npm test
npm run build
```

자동 검사는 생년월일/연령, 중복 ID와 오류행, 비밀번호 해시, 기관 배정 판단, 식별정보 제거, 비인증 차단, 다른 Origin의 쓰기 차단을 포함합니다. 실제 Firebase/Google/Vercel 운영 연결 검증은 별도로 필요합니다.

참고: [Firebase Admin SDK](https://firebase.google.com/docs/admin/setup), [Vercel Functions](https://vercel.com/docs/functions), [Google Sheets API](https://developers.google.com/workspace/sheets/api/quickstart/nodejs).
